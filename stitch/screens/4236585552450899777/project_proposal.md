2.Problem Statement

Mobility within the UNILAG campus using the newly introduced electric buses faces significant logistical challenges:
•Unequal Fleet Distribution: Buses frequently cluster at one bus stop (e.g., Campus) while students experience long, stagnant queues at other stops (e.g., Gate or DLI).
•Unpredictability: Students have no way to track bus locations or estimate arrival times.

•Poor Queue Management: Administrators lack real-time data on passenger queue lengths, making it impossible to dispatch buses efficiently to high-demand areas.

3.Proposed Solution

We propose Uni-Track, a Java-based web application tailored exclusively for managing UNILAG’s electric bus fleet. Key features include:
•Real-Time Tracking (Prototype): Using a mobile phone's GPS aboard the bus to broadcast live location data (scalable to physical hardware GPS in the future).
•Manual Queue Measurement & Dispatch: Bus administrators will input estimated crowd ranges (e.g., "0-5 people", "15-20 people") into the system at their respective stops.
•Dynamic Load Balancing: If an admin logs a high queue (e.g., 20 people at Gate) with no incoming buses, they can instantly ping idle buses at other stops (e.g., Campus) to request urgent relocation.

4.Project Justification

This system eliminates guesswork in campus transportation. By improving the operational efficiency of the electric buses, we reduce student wait times, prevent overcrowding, and maximize
the utility of the green transport fleet. It provides a structured, scalable approach to a daily problem.

6.Scope and Limitations

•In-Scope: Development of the web application, mobile GPS tracking prototype, and queue management modules for UNILAG electric buses at key stops (Gate, Campus, DLI).

•Out-of-Scope: Standard campus cabs and physical GPS hardware integration are excluded from this initial COS202 project phase.
